# @shres-code/shres-code-client-ui-trajectory

Trajectory renders a turn-aware event ledger with selectable User, Assistant, Tool, and nested Subtool records. Thick rules mark Turn boundaries, compact inline markers identify Steps, and the main ledger keeps only index, event, and content; selection opens a local inspector for token usage, duration, Input, Output, and Timing. In the raw source view, adjacent reasoning blocks of one assistant message coalesce into a single expandable Thinking entry with a segment count, collapsed by default and showing the newest segment's first line as a live preview while streaming. Scrollable Summary regions keep their scrollbar thumbs transparent until the region is hovered or contains keyboard focus, without changing the reserved scroll geometry. A standalone compaction request appears chronologically in its own `Between turns` section, while a numbered compaction remains inside its owning turn. Long ledgers open at the current tail, load one older page when the user reaches the loaded range's top, and mount only the visible row window plus a small overscan; request-only separators share the next measurable virtual item, while semantic row keys and ARIA indexes survive prepends. Selection, timeline navigation, folding, search, and Request totals cover the currently loaded window. The ledger covers records with an explicit loading row until the initial tail is positioned. While an older prefix remains unloaded, a first-row control precedes the loaded records, loads one earlier page on click, and changes in place to a disabled loading status while that page is pending. A fixed Overview above the ledger projects real record start/duration timing from left to right; when earlier records remain unloaded and the viewport includes the loaded domain's start, a neutral ellipsis control identifies the omitted prefix and loads one earlier page without assigning unknown history fabricated duration. Assistant spans divide recorded TTFT from decoding, and a 500 ms hover reveals exact clock and duration details. Dragging an interval focuses the ledger on every record active at any point in that inclusive range, while clearing the selection restores the full loaded ledger. Wheel gestures zoom the time domain. A right-button click clears the selected interval, while a right-button drag pans an already zoomed viewport without changing it. The initial view and streaming updates stay at the tail; scrolling upward suspends following so new records do not interrupt inspection of earlier rows. Content-only stream frames preserve virtual row keys and heights, reuse measurements, and do not issue repeated tail-scroll writes. Completed replies retain assembled blocks, timing, and usage in Trajectory target State, while the shared Session window keeps the raw Events. Trajectory asks the conversation shell to float the composer over the full-height ledger, while its responsive vertical scrollers reserve the composer's live height so final rows remain reachable. Trajectory-owned Definitions assemble business records, including cancellation-frozen Assistant and Tool records, from the shared Session window, so Trajectory neither reads nor changes the Chat conversation snapshot. A `shield/decision` event is folded onto the matching user, context, tool, or subtool row as a Blocked / Asked / Observed badge; a `jspace/card` or `jspace/closed` event is folded onto an existing row as an Open / Checkpoint / Closed badge; Input / Model / Tools lanes and Completed / Pending / Failed stay execution state. The package provides no service and declares no Context merge; it registers target-specific Event Definitions, a Trajectory view builder, and one tab in the conversation's `'conversation.view'` slot ring. Contract: api-contracts v3 §8.

Model routing renders in the ledger rather than the composer. Every logged `model-routing/decision` becomes a ROUTING row at its seq carrying the outcome, its reason class, the confidence of the judgment, the allowlisted route the decision selected, and a streak-entered or streak-ended transition as it happens. Successive step decisions are compared so a held route does not appear to enter again within its first turn. The request boundary row of every judged turn carries the effective provider/model the request actually used, badged Routed when that route differs from the sticky session selection; a kept-strong decision that changed nothing collapses to a quiet marker carrying the outcome and its reason class alone, so a session that only ever holds the strong route does not narrate every ask. Nothing here keeps routing state: the rows fold the decisions the host logged, and the router's vocabulary reaches this package through its client namespace. While a `routing` conversation view is registered (`canReveal('routing')`), every ROUTING row that carries its decision seq offers an Explain link, a native button reached by Tab and activated by Enter or Space, which reveals that decision's seq as an `event` target in the routing view; it keeps its click and activation keys from the row, so the row does not select itself.

A cross-view inspect request addressed to Trajectory opens the record summary and scrolls to the row, then acknowledges. A `call` target resolves to the record carrying that call id and stays pending until that record loads. An `event` target resolves to the loaded record with the greatest source seq at or before the target seq, which is the record the event produced or else the nearest earlier record; request-only separators never resolve a target. It stays pending while older history that could hold that record is unloaded and retries as pages load, since the view does not page history in on its own. When the whole history is loaded and no record precedes the seq, it is acknowledged without opening a record.

## Model Experience

None, as the trajectory views render session data in the browser; nothing here reaches a model request.

#### KV Cache effect

None; this package neither assembles nor sends a provider request.

## Known Limitations and Deferred Work

- **Routing rows read the loaded window** — each request compares its effective route with the latest same-turn decision that precedes its request anchor or belongs to its step, so a later step cannot badge an earlier request. A request whose preceding decision sits in an unloaded older prefix carries no effective route until that page loads.
- **In-flight Time stays blank** — `partial` and `runningCalls` rows show their running state without a fabricated duration, so the Overview renders a start marker rather than inventing a live span. Record and timeline selection are local to Trajectory, with no anchor deep links.
