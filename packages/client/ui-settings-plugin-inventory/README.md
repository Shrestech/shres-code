# @shres-code/shres-code-client-ui-settings-plugin-inventory

Two tabs for Web Settings' Plugins section, registered as localized `settings.plugins.tab` contributions sharing one dictionary namespace: the **Plugin list** tab with id `all` and the gesture-gated **Manage** tab with id `manage`. The Plugins section owns the navigation entry and tab chrome. Selecting a tab for the first time mounts it and lazily calls `ctx.remote.pluginAdmin.listPlugins()` or `ctx.remote.pluginAdmin.status()` through [`api-remotes`](../../api/remotes/README.md). The Plugin list uses the same managed rows for status and activation restrictions, so one host read cannot show stale enablement controls. Both tabs open under the top-level Plugins destination and use the full content width.

The Plugin list tab renders a searchable two-column catalog of compact disclosure cards. Each collapsed card uses the short module name as its title and a small effective-enablement tag; enabled entries also show a colored root-fiber status dot. Expanding one card reveals its Loader-tree entry id without a redundant field label, followed by the effective configuration and, for enabled entries, Cordis status. An addressable row offers an enable or disable action that spends a one-shot `pluginAdmin/begin` grant and calls `setPluginEnabled`; the host's restart-required, overridden, refusal, and read-only results remain visible. Disabled entries omit the redundant unmounted runtime state. The entry id remains the React key, disclosure identity, detail value, and an additional search target; it is never classified by string shape. Loading, empty, no-match, and generic failure states stay local to the mounted component, and a failed read can be retried without exposing transport details. The registration uses `ctx.slots.inject()`, so it follows late tab declaration, redeclaration, locale changes, and teardown without importing the section owner.

The Manage tab reads one pluginAdmin status snapshot and renders every profile plugin with its restart readiness, plus every installed skill with a visible shadowed-by source when a live skill outranks it. With mutations enabled on the host, it installs a package spec through a parked preview that needs explicit confirm or cancel, removes the plugins the status reports removable (a shipped template bundle row never offers Remove), and adds or removes local skills; each action spends a one-shot gesture grant from `pluginAdmin/begin`, and every action button disables while one operation is in flight, so no duplicate mutation can start. Refusal copy names the specifics: install scripts are never run, `link:` specs are refused, and a missing pnpm or an unsupported platform is stated as such. When the host reports plugin mutations as anything but enabled — the desktop app today — the plugin controls give way to "Plugin installation is not available in the desktop app yet." while skill operations stay available. A parked install seen only through status carries no confirm token on this client and renders read-only; the host's confirm window cancels such a transaction, and outcomes that settle after unmount are dropped because the host owns the parked transaction and every in-flight request. The install area states the consent terms plainly: installed third-party code runs with full access on every future start, and confirming authorizes the operation without proving that a person made the request.

## Model Experience

None, as this package only visualizes a Host-owned deployment snapshot in browser Settings and registers nothing model-facing.

#### KV Cache effect

None; this package neither assembles nor sends a provider request.

## Known Limitations and Deferred Work

- **One snapshot per Settings mount or retry** — neither tab subscribes to Loader or profile changes; switching tabs preserves the current snapshot, reopening Settings or retrying obtains a new one, and a settled mutation refreshes the status once.
- **Loader inventory grouping** — the Plugin list tab's local search adds no provenance, current-browser activation diagnosis, or grouping by source.
- **Plugin mutations need an enabled host** — the host needs pnpm on its PATH, Windows refuses plugin installs as unsupported, and the desktop app enables no plugin mutations yet; a transaction parked in another session is shown without controls because its confirm token never reaches this client.
