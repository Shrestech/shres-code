# Agent Note: Typed-judgment capability — Jev model routing and intelligent compaction

Status: proposed

## Problem

Two judgment calls per agent interaction are made by the cheapest possible logic today. **Which model handles this turn** is whatever the user selected once, applied to typo fixes and architecture work alike. **What survives compaction** is recency plus a token ratio, with no notion of which segments are load-bearing. A third problem surfaced from production billing: **prefix-cache economics dominate agent spend**, and both features interact with it. One 25.5-hour export (582 requests, $48.49) shows 42% of spend on uncached input from two multi-hour 0%-cache windows (250–624K re-prefills at list price; 54 full-miss requests caused 92% of uncached dollars) and 52% on cache reads — context size is a recurring subscription, and every model transition is a cold re-prefill.

A one-day live evaluation of TypeSafe AI's Jev (a "System One" decision model: text state + typed questions in, calibrated probabilities out, no generation) measured whether a rented classifier can make the two judgments. Headline results: 36/36 attacks caught on a 60-case labeled injection set with 2–3 borderline false positives; clean harmful-vs-benign command separation (0.63–0.99 vs 0.12–0.34); correct extreme-case routing at 1.0 confidence with honest low-confidence hedging on ambiguous prompts; **two adversarial tasks misrouted to the weak model at 0.97 confidence because the trap lived in fixture files, not the prompt**; borderline probabilities wobbling ±0.01–0.06 across identical reruns (their own consistency cookbook measures std dev 0.0102). Economics are a non-factor ($0.042/M input, output free; routing ≈ $0.21–0.71/day at the deployment's volume). Posture facts: TypeSafe retains Input with no zero-retention option, US-hosted, no training on Input; site terms clause (vi) restricts using the service to develop new products without written permission. The roster spread on the measured production workload is 8–75× (main $1.25/M input, $0.15/M cache-read vs a contributor variant at $0.10/M, $0.002/M), making routing value real there: a downgraded 300K-context turn saves ≈$0.075 against a ≈$0.04/day judgment cost.

## Proposal

Build one typed-judgment capability seam with two consumers plus a cache-affinity foundation, in six independently green PRs, all Jev packages opt-in composition only.

**PR0 — per-session cache affinity (no Jev dependency; attacks the 42%-of-spend churn class directly).** `llm-pi-ai`: the existing `onPayload` deployment hook's context gains `sessionId` (the documented OpenRouter recipe is then three lines of `!!js` in cordis.yml setting `prompt_cache_key`), and per-profile Config `promptCacheKey: "session" | "off"` (default `"off"`) emits the vendor cache-key field where the profile's protocol has one. `llm-deepseek`: `onPayload` parity for symmetry (its native automatic prefix caching needs no key). Per-seat API-key maps are deferred to the credentials seam with a Known Limitations line. Includes the teams cache-discipline docs section (batch review rounds; avoid sub-minute Lead↔seat alternation on one key; compaction for long-lived seats; per-seat `promptCacheKey` where supported).

**PR1 — the judgment seam.** `packages/llm/judgment` (Service Definition: `ctx.judgment` with a generic `choice | score | binary` vocabulary, an optional `ctx.judgmentRedactor` hook, no session events, no vendor names) and `packages/llm/judgment-typesafe` (provider over raw `POST /v1/systemone` fetch; per-call credential resolution through the credentials seam, never cached; timeout/abort composition; wire validation with `JudgmentError` codes UNCONFIGURED/UNAVAILABLE/INVALID_ANSWER/ABORTED; Config tier mapping `fast: jev-preview` / `accurate: jev-latest` — preview measured 273ms vs 685ms on a 1.7k-token state). The provider owns transport and zero prompt text; every question string is validated Config on the consuming package, which is what makes a future `judgment-local` distilled on-box engine a pure composition swap. The Definition also registers the `judgment` settings namespace (via `installSettingsSection`, the agent-default-model pattern) carrying `enabled: boolean` (composition default `true`): the deployment-level on/off surfaced in the Model UI Classifier section (PR4b). Consumers read it live through a `source()` closure and treat `enabled: false` exactly as engine-absent — routing resolves `kept-strong`, compaction-jev runs its documented byte-identical basic-degradation path — so the toggle reuses the degradation matrix instead of adding a third behavior mode.

**PR2 — asymmetric, cache-sticky model routing.** `packages/llm/model-router` plus the optional `ctx.get('modelRouting')` consult inside `installModelSelection` (`packages/core/agent/src/model-selection.ts`; no agent-loop change). Base policy (asymmetric): the manual/default selection is always the strong model; `candidates` is a downgrade allowlist and therefore the enforcement point — `resolveRequest` can return an allowlisted candidate or nothing, never the manual route and never anything stronger. Downgrade requires `confidence ≥ downgradeThreshold` **and** `top1 − top2 ≥ downgradeMargin` (documented operating points ≥0.8 / ≥0.1, above the measured ±0.06 wobble); every uncertainty class resolves to `kept-strong`; a Jev choice equal to the current route resolves to `kept-strong`.

  Stickiness (the hysteresis layer, motivated by the transition-cost arithmetic: a downgraded turn saves ≈$0.075 while a transition costs a $0.35–0.69 re-prefill at production context sizes, so a downgrade must persist ≈5–10 turns to net positive): sticky state is a **pure fold** `stickyState(events, config)` over `model-routing/decision` + `request/header` + turn events — resume/fork/compaction-safe, zero live memory. Transitions: `STRONG → DOWNGRADED(candidate, enteredTurn, entryBase)` when a turn passes the downgrade gate; `DOWNGRADED → STRONG` when (`turnsElapsed ≥ minTurnsDowngraded` **and** the turn fails the gate), or **immediately at any elapsed count** when `difficulty.score ≥ escalateBack.scoreThreshold`, when the session's manual provider/model deviates from `entryBase` (**provider/model comparison only** — unrelated header changes such as plan-mode toggles must not break a streak), when `model-routing/mode` flips off, or on a durable route-failure streak `≥ maxRouteErrors` (PR2 names exactly which provider-failure classes are durably logged and documents any that degrade the trigger). While DOWNGRADED the per-turn judgment call **continues and the difficulty question is mandatory** (`difficultyInstructions` required at load when `minTurnsDowngraded > 0`) — a sticky session never runs blind; the intra-turn pin is unchanged (one decision per turn, reused by later steps and retries). `escalateBack` acts; `hardHint` only hints in the UI while STRONG and never acts. New Config: `minTurnsDowngraded` (≥0; **0 disables stickiness and keeps the non-sticky design reachable/falsifiable**; documented 5), `escalateBack.scoreThreshold` (1–5; documented 4), `maxRouteErrors` (≥1; documented 2). Decision event gains `sticky: { active, turnsElapsed, enteredTurn?, brokenBy? }`. No transition-cost estimator and no rate-ratio table: realized transition usage is read from existing `assistant/message` usage by bench, never predicted by product code.

**PR3 — intelligent compaction.** A behavior-preserving refactor of `compaction-basic` promoting range selection to a protected `selectRange` hook (default body is exactly today's logic; suite green unchanged; new test proves a subclass override is honored at event time), then `packages/compaction/compaction-jev`: `JevCompactionEngine extends BasicCompactionEngine`, registered as `ctx.compaction`, composition-swapped for the basic row. It adds semantic segment scoring with rescue (chunked fan-out, `maxSegmentsPerCall` questions per call, boundary questions riding the same chunks), conservative-band boundary judgment (probabilities in `(threshold − margin, threshold)` count as unsafe, adjustment capped, tool-pairing always revalidated), and a verify-then-escalate summary cascade (purpose-scoped cheap draft → Jev preservation battery → one escalation to the strong route → `onVerifyFailure: accept-logged | fail-attempt`). Degradation is exact: with the judgment engine absent, erroring, or below confidence, behavior is byte-identical to `compaction-basic`, asserted by a twin-run diff test. Two companion log-only events (`compaction/selection`, `compaction/verification`); the shared `compaction/*` vocabulary stays backend-neutral.

**PR4 — bench.** `route-off/route-on` and `compact-basic/compact-jev` arms (insert-not-patch overlays), integrity presence checks, and `bench/jev-preregistration.md` written before spend. Decision rules: routing is GO iff McNemar non-inferiority at −5 points (interval excluding it), ≥15% token reduction on downgraded trials (netted by construction — billed tokens include transition re-prefills), adoption ≥2/3, the **churn screen** `cacheHitShare(route-on) ≥ cacheHitShare(route-off) − 5 points` applied only when ≥80% of trials in both arms carry usage data (otherwise declared not-evaluable in the preregistration and the token-delta rule carries the economic case alone — never silently skipped), and **any adversarial-stratum regression is an automatic NO-GO**. The non-sticky arm is NOT run: the preregistration carries the break-even arithmetic verbatim (54 full-miss requests = 92% of uncached dollars; 250–624K re-prefills vs ≈$0.075/turn saving; ±0.06 wobble guarantees sub-break-even flapping), and `minTurnsDowngraded: 0` keeps the claim falsifiable. New diagnostic metrics: `cacheHitShare` (nullable), `modelTransitions`, `downgradedStreaks`. Compaction-jev is adopted iff ≥+10-point verifier-passed delta on `pressureFired` trials with the interval excluding zero, tokens within 1.2×, verification adoption ≥2/3. Optional `promptCacheKey` overlay variant for the routing arms.

**PR4b — classifier models in the Model UI.** Judgment engines are first-class, role-bound models, following the agent-seats / purpose-binding precedent: model metadata gains a capability marker (e.g. `capabilities: ['judgment']`) on catalog entries, the composer model directory filters classifier-tagged models OUT of the conversation picker (a non-generative model must never be selectable for a turn), and a new "Classifier" section of the Settings models page binds the judgment engine model per deployment (resolved by the judgment consumers like seat bindings resolve theirs) and carries the deployment-level **on/off toggle** (the `judgment.enabled` field owned by the Definition's settings section from PR1; the `judgment` namespace joins `PRODUCT_SETTINGS_NAMESPACES` in the same PR so the section is remotely readable/writable). Two engine variants sit behind the unchanged `ctx.judgment` interface: the direct systemone provider (reference) and an OpenRouter-route engine (one key, one bill, PR0 cache affinity) — the latter gated on the OpenRouter exposure shape: `openrouter.ai/typesafe/jev-latest` has a page but is absent from the public model list and its endpoints API 404s at design time, and if the route exposes only plain chat completions without typed probabilities/confidence (or logprobs sufficient to reconstruct them), the calibrated contract the gates rely on does not transfer, so direct systemone stays the reference until the wire shape is verified.

**PR5 — the composer chip.** `packages/client/ui-model-routing` in a new `conversation.input.modelRouting` seat (plan-mode mirror), projection-driven, toggle in both states, hint line from `last.hint`, and sticky display (`auto: <model>, turn 3 of ≥5`) from the folded sticky fields; self-hides when the host composes no routing, so the roster row is safe to ship.

## Alternatives considered

**Symmetric routing ("the classifier picks the model").** Rejected on measured evidence: prompt-only judgment misrouted injection-trap tasks to the weak model at 0.97 confidence because the trap lived in files, not the request. Downgrade-only with a high threshold plus margin makes the worst case "a simple task over-served by the strong model" — cents, not safety.

**An "Auto" pseudo-row in `session.selectModel`.** Rejected: `ModelSelection` is a concrete provider/model/effort triple across the wire, settings, and directory state; an auto sentinel forks every contract and conflates which model with who decides. The plan-mode pattern (logged mode event + command + projection) carries the toggle with zero wire changes.

**A competing `agent/request` waterfall listener.** Rejected: Cordis waterfalls return through the first-registered listener, and `installModelSelection` rewrites provider/model after `next()`, so a separately registered router is silently overridden. The consult puts routing at the one point that already owns the final rewrite.

**Session-granularity routing (route once per session, pin forever).** Rejected by the red/green debate: it kills churn by construction but strands a session that starts easy and turns hard for *hours*, strictly worse than any bounded streak, and it forfeits the measured value case — the production workload is a read-heavy loop where adjacent turns differ in difficulty. The sticky fold keeps churn control without surrendering per-turn re-entry.

**A transition-cost estimator with per-candidate rate ratios.** Rejected: ratios are provider-controlled and go stale exactly like prices (the repo refuses a price table because stale prices are wrong prices), expected-remaining-turns is unknowable, and a wrong estimator vetoes good downgrades with no feedback loop. The operator sets an amortization horizon (`minTurnsDowngraded`) with the arithmetic documented; realized costs are measured from usage logs, and the bench churn screen is the net-effect check.

**Session-level sticky state in memory (extending the WeakMap pin pattern).** Rejected: cross-turn state that influences model requests must reconstruct from the durable log (model-visible ⟺ logged, resume/fork/compaction). The sticky state is a pure fold over decision events, request headers, and turn boundaries; the per-turn pin remains only as the intra-turn projection of that fold.

**A non-sticky bench arm.** Not run: the failure sign is arithmetic on already-logged invoices (250–624K re-prefills vs ≈$0.075/turn saving; wobble-driven flapping below the ≈5–10-turn break-even), not a statistical claim worth spend. The preregistration carries the arithmetic verbatim and `minTurnsDowngraded: 0` keeps the claim falsifiable.

**Uniform `promptCacheKey` adapter config across all providers.** Rejected: vendor semantics differ (OpenRouter body field, DeepSeek automatic prefix caching, others none); a uniform field is dishonest where no vendor field exists, and a new capability seam would be a one-consumer smell. The escape hatch (`onPayload` + `sessionId`) plus first-class fields only where the vendor field is known is the smallest honest form.

**`@typesafe-ai/sdk` as a dependency.** Rejected per the dependency policy: one endpoint with no retries/pagination deletes ~30 lines while importing a client lifecycle the provider would wrap and test anyway.

**Duplicated Jev HTTP per consumer.** Rejected: credentials, timeout/abort, wire validation, and the tier table are four owned surfaces that would drift in lockstep, and the local-engine leg would need swapping two packages per composition. Two current consumers justify the general seam; the redaction hook gets one home.

**Copying `compactIfNeeded` into compaction-jev.** Rejected by the duplication gate: ~90 lines of retry/overflow/transaction machinery would fork. The protected-hook extraction is the minimal change that lets the subclass inherit them.

**Burying the judgment engine in cordis.yml.** Rejected in favor of the Model UI binding: the engine model is a deployment-varying, role-bound choice, and the seat/purpose-binding pattern already owns that gesture; a cordis-only model id would be invisible to operators. The composer picker is deliberately NOT the surface — classifier models are filtered out of it by the capability marker, because a non-generative engine cannot serve a turn.

**Adaptive compaction triggering in v1.** Deferred: it changes *when* compaction fires, the bench verifiers measure *what* survives, and bundling it would confound the Stage-1 experiment against the forced-compaction overlay calibration. The seam keeps it a small later addition.

## Acceptance criteria

- PR0: `onPayload` hook context carries `sessionId` in both adapters (translation unit tests); `promptCacheKey: "session"` emits the vendor field only on profiles that declare one; the OpenRouter cordis.yml recipe is documented in the pi-ai README; teams cache-discipline section lands in the agent-team README.
- `judgment-typesafe` boots through the Loader against a loopback stub server; request/response mapping, tier table, redactor-when-composed, per-call credential re-resolution, and the error-code matrix are unit-covered; a self-skipping live e2e hits `/v1/models` and one `ask`.
- Routing: the asymmetric matrix is unit-pinned at exact gate boundaries (`≥` semantics on both axes); the sticky fold is unit-covered for every transition (gate-failed after horizon, difficulty at any horizon, provider/model deviation, mode-off, route-error streak) and proven pure (identical fold from a replayed log after simulated restart); `difficultyInstructions` absent with `minTurnsDowngraded > 0` fails at load; REAL-composition drives a turn against the stub server with decision events matching the consumed `request/header`; the keyless snapshot pair shows ON downgrades in-transcript and OFF byte-identical.
- Compaction: the degradation matrix (engine absent / UNAVAILABLE / INVALID_ANSWER / below-confidence) diffs span + summary against a `compaction-basic` twin byte-identically; the cascade paths (accepted / escalated / accepted-below-threshold) are covered; `maxRescues: 0` disables rescue.
- Bench: `bench/jev-preregistration.md` merges before any spend, carrying the churn screen, its ≥80% evaluability rule, and the break-even arithmetic verbatim; dry-run renders for all arms; integrity presence checks fail arms whose packages never logged.
- Chip: hidden without the projection key and for subagent sessions; toggle executes `/route on|off`; sticky display reflects the folded state; `test:gui` + replay `test:web` green; GIF per the GUI convention.
- Every PR carries an Agent Note update and package READMEs (Model Experience, Known Limitations); nothing Jev-related ships in default bundle rows.

## Risks

- **Workspace-blind judgment** (the motivating finding): mitigated by the allowlist-as-enforcement design, the margin gate, and the adversarial NO-GO clause; a residual miss class (simple-looking dangerous request) is documented in the model-router README.
- **Stranding on a cheap model mid-streak**: mitigated by the mandatory per-turn difficulty question while downgraded with immediate escalate-back, the provider/model deviation exit (user authority always wins), and the route-error streak exit; the failure-class durability gap is a named PR2 verification task.
- **Stickiness realized savings assumed, not measured**: mitigated by the churn screen with its frozen evaluability rule and by sequencing PR0 first (cheaper transitions shrink the cost hysteresis amortizes); `minTurnsDowngraded: 0` keeps the design falsifiable.
- **Privacy posture**: TypeSafe retains Input with no ZDR and hosts in the US. State caps and `segmentMaxChars`/`verifyMaxChars` bound egress, the redactor hook has one home in the seam, the credentials seam keeps keys out of configuration, and `judgment-local` (distilled on-box engine) is the stated endgame for governance-sensitive deployments.
- **Terms of use**: site terms clause (vi) restricts using the service to develop new products without express written permission. Evaluation and BYOK experimentation proceed; shipping a product integration waits on the partnership conversation (which also owns ZDR-for-enterprise, subprocessor disclosure, and volume pricing).
- **Model jaggedness** (from the vendor's own model card): no reliable counting or math, dates read as text, accuracy falls with large irrelevant state, adversarial content in state moves answers, and structural invariants do not hold (noul-vs-choice disagreement, probabilities summing past 1). Design consequences already in the plan: arithmetic stays in code, states stay focused and capped, noul thresholds never transfer to choices, criteria text is validated Config tuned with evidence.
- **Nondeterminism**: borderline answers wobble run-to-run; all gates use margins, and no threshold sits at 0.5.
- **Cost**: deliberately not a risk factor at measured prices (routing ≈ $0.21–0.71/day); the bench gates effectiveness, not spend.

## Implementation record (PR0, PR1, PR2, PR3, PR4, PR4b, and PR5)

PR0 shipped the payload-hook context change in both adapters and the pi-ai profile field. `promptCacheKey: "session"` emits the vendor cache-key field where the requested model's wire protocol declares one — today the OpenAI-compatible chat-completions protocol's `prompt_cache_key` — and emits nothing on a protocol with no such field, because an Anthropic-style protocol carries cache breakpoints inside the request body rather than in a key. The OpenRouter recipe is three lines of `cordis.yml` (`promptCacheKey: session` under the route), optionally written as a `!!js` expression; the `onPayload` hook context (provider, model, sessionId) remains the escape hatch for a vendor spelling the protocol table does not cover, and a wrapper plugin is what consumes it.

PR1 shipped the seam and the Jev provider. The vendor wire facts were verified against TypeSafe's published API reference: `POST /v1/systemone` takes `{ state, model, questions }` with `noul`, `choice`, and `score` questions, answers return per question id, and confidence is reported only for choice and score answers because the vendor derives it from a distribution — a noul answer carries its probability alone, which the seam vocabulary mirrors. The provider resolves its credential per call, composes the caller signal with its configured timeout, validates the response per question kind, and maps every non-2xx status to `UNAVAILABLE`. The Definition owns the `judgment` settings namespace described above, and its subsystem page plus the catalog registrations ship with it.

PR2 shipped `packages/llm/model-router` as both the Definition of routing state and a Consumer of `ctx.judgment`: the two log-only events (`model-routing/mode`, `model-routing/decision`), the pure folds (`foldModelRouting`, `stickyState`), the consult inside `installModelSelection`, the `/route` command, the `modelRouting` projection, and the `model-router` settings namespace. The consult is reached through a structural `ModelRoutingConsult` interface declared in `packages/core/agent` (`ctx.get('modelRouting')`), so the loop's own package keeps no dependency on the router while the router asserts conformance to the consult in its own compilation. The route question text, the difficulty question text, and the difficulty levels are Config on the consumer, which is what keeps the provider free of prompt text.

Two PR2 details resolve wording the plan left open. First, the streak's entry base is derived in the fold from the last `request/header` before the entering decision: while a streak is held, routing rewrites the header to the candidate, so the manual route is only recorded there while the state is strong — the fold therefore reconstructs `entryBase` rather than reading it from a live mirror, and the live consult compares only `provider`/`model` against it. Second, the decision's `engine`, `model`, and `latencyMs` are optional because a `skipped` or engine-absent decision makes no call, and `skipped` is written only for the one reachable case (the mode turned off under a turn that already had a pinned decision); a turn judged while the mode is off writes nothing, which is what keeps a composed-but-off run byte-identical to one without the package.

The failure trigger names exactly which classes are durable: consecutive `turn/end` reasons of kind `error` whose code is neither `ABORTED` nor `UNKNOWN`. `llm/retry` events (a retried attempt, not a failed turn), prunable error finish chunks, and `aborted` turns are deliberately not counted, and a failure a recovery listener absorbs without scheduling a retry — canonically `compaction-basic`'s context-window recovery — leaves no `turn/end` error, so the streak does not advance. That gap is documented in the package README as a loud degradation rather than a silent one.

PR3 shipped the hook and the provider. `compaction-basic` promotes range selection to a protected `selectRange` hook whose default body is the shipped head-anchored selection, and the hook returns a promise because a judgment-backed override must await an engine before it can decide; returning `null` declines the attempt, so a subclass that finds nothing worth compacting costs no summarization call. `compaction-jev` extends the basic engine as the `ctx.compaction` implementation, composition-swapped for that row, so the inherited listeners, durable transaction, retention, overflow recovery, and shrink validation are reused unchanged and only selection and summarization are overridden.

Selection partitions the inherited baseline span into step-bounded, tool-pairing-balanced segments, scores them for load-bearingness with `maxSegmentsPerCall` questions per ask, and rescues the segments at or above `rescueScore` whose confidence reaches `segmentConfidence`, up to `maxRescues`; the rescued segments merge into contiguous sub-spans that the inherited machinery compacts tail-most-first, one per call, which is what keeps the retry and rollback semantics those of the base class. One hazard question per sub-span edge judges the boundary conservatively — a probability inside the `boundaryMargin` band below `boundaryThreshold` counts as unsafe — and an unsafe edge moves outward to the nearest legal pairing-balanced position within `maxBoundaryAdjustment` nodes, or stays where it was when no legal move exists inside that cap.

Summarization keeps the inherited draft and then verifies it: the configured binary checks plus one overall score question read the draft against the capped original region, all checks at or above `verifyThreshold` together with an overall score at or above `verifyScore` accept the draft, and a failure spends at most `maxEscalations` escalations on `escalationProvider`/`escalationModel` — or the conversation target when both are omitted — before `onVerifyFailure` either records the failure and returns the better-scoring draft (`accept-logged`) or throws and fails the attempt (`fail-attempt`). A band-only failure, where nothing sits below the threshold but something sits inside `verifyMargin` of it, spends no escalation under `accept-logged`.

The provider's two companion events are log-only and append-only, and neither extends `SurfaceEventType`. `compaction/selection` records the trigger, the degradation class, one fact per segment (span, score and confidence when it was scored, and disposition), the boundary moves, and the engine and model that answered with their latency; `compaction/verification` records the compaction id, the 1-based attempt, the verified draft's route, the battery answers with `overall` last, the verdict (`accepted`, `escalated`, or `accepted-below-threshold`), and its own degradation class. Both are registered in `known-event-types.ts` and the persistence catalog, so the shared `compaction/*` vocabulary stays backend-neutral. The package's `./invariant` companion asserts the cascade relation at `internal/dispatch`, before publication: a compaction that closes without an error never leaves its latest verification reading `escalated`.

Degradation is exact and decided per step. An absent engine, `judgment.enabled: false`, an engine failure, an unusable answer, a score below `segmentConfidence`, a plan that rescues nothing, or a boundary ask that cannot be answered all leave selection on the inherited span; an absent or disabled engine, an `INVALID_ANSWER`, or an unreachable engine leaves summarization on `super.summarize`. Each case writes `degraded: true` with its reason class on the companion event, so a degraded run is the `compaction-basic` run.

PR4 wires the bench to both claims: `route-off`/`route-on` and `compact-basic`/`compact-jev` arms whose treatment rows live in pinned overlay files the runner reads and emits verbatim (so the pin and the applied composition have one source), adoption presence checks in the arm-integrity audit (routing arms expect a decision on any turn-bearing session, the jev arm expects a verification whenever a session compacted; a violation is recorded on the trial, never aborting it), eight nullable Jev metrics with their per-arm aggregates, a chain-trial rollup that re-folds the concatenated phase logs (counters summed, shares recomputed from the totals, transitions counted across the boundary, streaks concatenated per phase), arm-declared judgment credential references resolved exported-first and otherwise from the harness store with the value injected into the child environment alone, and a verdict block that computes the pre-registered rules — H4's ≥80% evaluability screen, H3/H6 adoption at two thirds, H2's paired token delta over the downgraded subset, H5's paired pressureFired pass-rate delta with the 1.2× ceiling — with every record either `evaluable` or `not-evaluable` carrying its reason, never a silent pass. `bench/jev-preregistration.md` fixes the decision rules and the preconditions before any spend, and states that a run without a live key is not evidence.

PR4b exposes the Definition's `judgment` settings section through the Web settings plane (the namespace joins the proxy's product allowlist) and adds the Classifier card to the Settings models page: the deployment switch whose copy states that off treats the engine as exactly absent, writing through the page's normal settings path. Model metadata gains an optional `capabilities` marker, and the shared model directory filters an engine-tagged entry out of the conversation picker and the `/model` popup; no adapter emits the marker yet, so the filter is inert until a vendor lists such a model. PR5 adds `packages/client/ui-model-routing` and the `conversation.input.modelRouting` seat: a chip that reads the host-computed `modelRouting` projection only and never keeps a local copy of routing state, shows `Auto` and runs `/route on` while routing is off, shows the routed selection, its confidence, the held streak and the hint while it is on, hides when the projection is absent and for addressed subagent sessions, and surfaces command failures inline. It renders `turn N` rather than `turn N of ≥M` because the projection publishes no horizon, and the shipped composition mounts no router, so the seat draws nothing until one is composed.
