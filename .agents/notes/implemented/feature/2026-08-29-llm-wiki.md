# Agent Note: LLM Wiki as project long-term memory

Status: implemented

## Problem

The harness already has an episodic session log and a J-Space working card. It has no durable, searchable store of project knowledge that survives compaction, card ship, and session end. WikiSkill ([arXiv 2608.27454](https://arxiv.org/abs/2608.27454)) showed that a persistent knowledge wiki between raw traces and skills raised benchmark scores (up to +24 pts; 9B + wiki beat 27B without) when the wiki is maintained and never injected wholesale into the prompt. A live gorakh-v2 wiki that computed temperature but never demoted, used the frontier model for librarian work, and left `touched` as an honor system, ended with hundreds of COLD pages and zero HOT ones.

## Decision

A new `packages/wiki/` group is the long-term knowledge tier. `ctx.wiki` is a complete capability seam: Service Definition, filesystem provider, tool Consumer, optional ONNX embeddings, and a cheap-model librarian seat. Wiki markdown lives at `<projectRoot>/.shres/wiki` beside skills, where the project root is the `.git`-walk root of the calling session's recorded `cwd` ([per-repo roots and JSONL day logs](./2026-08-29-wiki-per-repo-jsonl-day-logs.md)). The directory is created on the first write. `enabled` defaults true; `enabled: false` unloads tools and refuses dispatch.

Wiki content reaches the model only through `wiki_search` / `wiki_read` / `wiki_write` / `wiki_log`. There is no system-prompt section. `wiki_read` bumps `touched` itself.

Temperature, archive demotion, lint, index regen, log rotation, and BM25 search are pure folds — zero LLM tokens. COLD-past-`demoteDays` pages move to `archive/` and are never deleted. `index.md` is a generated, size-capped projection.

Semantic search, when `@shres-code/shres-code-wiki-embed-onnx` is mounted and available, mixes cosine with BM25. Absent embeddings is BM25-only, not an error.

The librarian runs one batched auxiliary `ctx.llm.stream()` call per cycle on a user-bound route (settings `wiki.roles.librarian` → project `config.yaml` → plugin Config). Unbound is dormant: it never uses the session frontier model. A `wiki/librarian-request` event is logged before dispatch. Triggers: successful `jspace_ship`, session dispose, and an optional `ctx.jobs` registration of the same inflight cycle.

Settings → J-Space hosts the LLM Wiki toggle and, only while enabled, provider/model pickers over every configurable route including Ollama Cloud. Nothing is bound by default.

### WikiSkill mapping

WikiSkill's wiki sits between traces and skills and is maintainer-consolidated, never wholesale-injected. This seat copies that placement: session log and shipped cards are traces; wiki pages are durable knowledge; wiki→skill graduation is deferred behind `verifyDecisionRule`. Consolidation is a cheap-model batch, not a per-write LLM call.

### Nine gorakh lessons

1. Librarian work is dispatched on the bound cheap model, or not at all.
2. Decay demotes COLD-past-`demoteDays` pages into `archive/`.
3. `index.md` is generated; there is no hand-maintained search sidecar.
4. Lint (orphans, dead links, freshness, index drift) runs on write and during the librarian pass.
5. The index is size-capped; JSONL log shards rotate at the local day boundary.
6. The read path records `touched`; the model cannot set it.
7. Verification and consolidation are batched on the cheap model, never inline per work item on the frontier model.
8. The wiki holds durable knowledge only — no task tracker, no card mirror.
9. Contradiction is structural (`contradicts` / `superseded_by`); the librarian re-synthesizes pages.

## Alternatives considered

**Inject the wiki into the system prompt.** Rejected because WikiSkill's ablation and the model-visible ⟺ logged rule both require tools as the only path, and wholesale injection is a token tax that compaction cannot save.

**Fall back to the session frontier model when unbound.** Rejected because that recreates gorakh lesson 1: librarian work silently burns the expensive model. Unbound is dormant.

**Store wiki under `.shres-code/wiki`.** Rejected because the only project-local convention is `.shres` (`<projectRoot>/.shres/skills`). Wiki sits beside skills.

**Hand-maintained search.jsonl / nodes sidecars.** Rejected because they drifted. One generated index is the source of derived navigation.

**Per-write LLM summarization (A-MEM).** Rejected because that is the anti-pattern: one batched call per cycle is the token budget.

**A `JspaceCard` field for enablement.** Rejected because the card is per-session working memory; wiki enablement is project/global settings state.

## Consequences

Any profile that omits wiki packages still boots. A new session in a repo with the seat mounted has the toggle on and no `wiki/` directory until the first write. Search ranks HOT above COLD. Archive remains on disk. Every wiki LLM call has a preceding `wiki/librarian-request`; every write has a `wiki/page` event.

`ctx.wiki` is host-owned in the base bundle (same plane as J-Space). A preset row would publish a process-global service and fail the agent-preset mount audit, so the researcher preset does not remount it. The librarian stays dormant until the user binds a route on the J-Space page.

## Testing

Package specs cover the temperature/demotion/lint folds, filesystem lazy materialize, tools remount, embeddings mix-in, librarian route resolution and cycle, and Loader composition for the tools. Client specs cover the LLM Wiki toggle and gated model pickers. `examples/headless-agent` keyless snapshot `wiki-tools` is the assembled transcript for `wiki_write` → `wiki/page`.
