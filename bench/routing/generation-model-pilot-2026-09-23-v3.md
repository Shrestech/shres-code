# Generation model routing pilot v3

This registration measures task outcomes on the configured ZAI `glm-5.3` and Ollama `deepseek-v4-flash:cloud` services. It preserves the [v2 tasks, runtime configuration, process checks, and budgets](generation-model-pilot-2026-09-23-v2.md). The identifier is `generation-model-pilot-2026-09-23-v3`, with fresh immutable registration and run directories. Both earlier registrations and their results remain unchanged.

The installed pi-ai 0.84.1 OpenAI-compatible stream adapter records `responseModel` only when a provider chunk names a different model from the request. An absent field therefore cannot distinguish a matching echo from an omitted name. V3 accepts unknown backend identity for both configured services while rejecting observed model-name drift; request headers and assistant provenance must still match the configured route. No result claims immutable weights or a proven backend revision. This fixes the v2 readiness rule that rejected a normally completed ZAI trial because matching-name metadata was unavailable.

The two readiness cases must each resolve the task, record process exit zero without timeout or budget termination, and end with a completed turn. Source, task, tier, and registration choices are checked before and after each canary. Main launch requires both canaries to pass and retains source/input checks around each model run. Run `node bench/routing/model-pilot.mjs plan`, then `canary --execute`, then `launch --execute`; `analyze` reads completed artifacts.

The main comparison has six tasks, three repeats, and two services: 36 trials and 42 process spawns, with a 120,000 observed non-cache-token cap per spawn. It supplies descriptive task-outcome data for routing development. It cannot authorize default JEV replacement, security promotion, or a claim that either service is universally superior. A separate held-out routing comparison remains required.

The completed pilot has 36 label-eligible trials and no infrastructure errors. ZAI GLM resolved 18/18; Ollama DeepSeek resolved 17/18. Across 18 pairs, GLM has one exclusive success and 17 ties. Mean recorded durations are 104.26 seconds for GLM and 74.88 seconds for DeepSeek; mean reported non-cache token counts are 29,875.83 and 44,121.50. Neither service reports an independent backend revision. These task repeats do not establish independent generalization, billed cost savings, or routing superiority.
