# Routing measurement — draft preregistration (prereg-2026-10)

This document records the candidate PR 16 routing measurement before any real
(non-dry) trial runs. It is a draft dated 2026-09-27, not a frozen
preregistration: the owner has not selected the budget or completed the method
decisions. The gate math is implemented in `bench/analysis/routing-gate.js`, the gap sampler in
`bench/runner/gaps.js`, and the arms in `bench/runner/arms.js` with their
pinned overlays in this directory. The machine-readable half is
`prereg-2026-10.registration.json`.

## Question and decision rule

On quota routes, does cold-point routing with the local Laya judge reduce
strong-model tokens without a meaningful loss of task success, compared with
always-strong? PR 17 turns routing on by default only if every gate below
passes. Otherwise the default stays `off`, and shadow is recommended.

## Task suite

Source: `bench/tasks/routing-multiturn/`, 60 tasks of 3–8 scripted user turns
with one deterministic verifier run after the last turn; per-turn checkpoints
are a secondary measure. Strata: 20 routine, 20 moderate, 20 hard, labelled
before the calibration run by two independent labellers, disagreements to
hard. L3 only: 15 tasks that delegate naturally, for arm T. Discrimination
filter (calibration run, 1 repeat of S and C over 80 drafted tasks): keep the
60 where C fails at least 30% of the hard stratum, C fails at most 10% of the
routine stratum, and S passes at least 80% overall. A suite at ceiling cannot
measure harm; a suite that fails the filter is redrafted, not re-filtered.

## Idle gaps

Between turns the runner sleeps for a gap drawn from the logged
start-to-start distribution (29.4% over 300 s, 5.7% over 3,600 s), frozen as
these cumulative anchors (seconds → CDF): 0 → 0.0, 60 → 0.28, 180 → 0.52,
300 → 0.706, 600 → 0.80, 1200 → 0.87, 1800 → 0.91, 2700 → 0.93,
3600 → 0.943, 5400 → 0.965, 7200 → 0.978, 10800 → 0.99, 21600 → 1.0. The
two measured quantiles are exact; the interior anchors interpolate that
logged distribution and are replaceable only before the calibration run.
Draws are seeded and logged per trial; the seed is derived per
(task, repeat) from the experiment gap seed, so paired arms share a trial's
gap structure. Every task gets at least one gap over 300 s (the sampler
redraws its last gap from the tail stratum when none lands there; the redraw
is part of the frozen rule). Gaps are capped at 20 minutes in L1 and L2
(`--gap-cap-ms 1200000`); the drawn value stays logged, the over-1-hour
stratum is then truncated, and the report names it unmeasured. L3 runs real
gaps for draws over 1 hour. Gaps elapse from the runner's submission of the
previous turn, which is the start-to-start convention the distribution
measures.

## Cache isolation

Arm order is randomized per task with a seeded shuffle (`--arm-seed`; the
seed is pinned in the manifest). Each strong arm uses a separate Anthropic
API key (see Arms). A per-arm nonce line goes in the first user message of
every trial (`--nonce`), logged and model-visible, so provider caches do not
carry across arms; trials that record a first-request cache read they did not
create are flagged in the report. Temperature is never set. Variance comes
from repeats, and within-task variance is reported per arm.

## Offline judge replay (free; before the confirmatory run)

`bench/routing/calibrate.js` renders every cold-point state from the calibration run's S and C trials with the router's own renderer; its hosted frontend uses `bench/routing/replay-judge.js` for Laya fitting. The label cheap-sufficient: C passed the task, and C's trajectory from that cold point reached the next cold point with no worker-escalation trigger. Reported: AUROC, ECE, the coverage vs false-downgrade curve, the truncation rate (only the current entry fit), and head tokens. Laya gate: AUROC ≥ 0.70; at the chosen point, false-downgrade ≤ 10% with coverage ≥ 15% of cold points. ECE is reported against the preregistered 0.10 bound as `within-bound` or `curve-only`; thresholds are always empirical values from the replay curve, and a curve-only reading does not fail the gate. If AUROC, the feasible-point leg, or the coverage leg fails, routing stays shadow-only and the confirmatory run is skipped. The operating point — the threshold and margin that maximize coverage subject to false-downgrade ≤ 10% — is written by
`bench/routing/write-registration.js` and by nothing else: the calibration
driver passes its evaluated metrics to that writer, which is the sole writer of
the registration's `calibratedBy` id, R's threshold and margin, and N's matched
rate, and writes them only when the Laya gate passes. The
provisional overlays ship the point with NO `calibratedBy`, because in the
router that key's presence alone marks a point calibrated; the runner refuses
confirmatory trials unless the registration records a passed gate, the
overlay's id equals the registration's, and the overlay's values equal the
registration's, with N's rate equal to R's realized entry rate.

## Hypotheses and gate

All methods are the ones `bench/analysis/routing-gate.js` implements; the
module is the method of record.

- H1 (primary, non-inferiority). Paired by task and repeat, the lower bound of
  the one-sided 97.5% interval for success(R) − success(S) is above −5
  points, overall and in the hard stratum. The interval is cluster-robust by
  task (CR1).
- Secondary hypotheses, tested only if H1 passes, Holm-corrected at family
  α = 0.05, each contributing the one-sided p-value its module section
  states: H2 success(R) > success(N) at the matched rate; H3 strong quota
  tokens R/S ≤ 0.80 with a 95% interval excluding 1; H4 added p95
  critical-path latency ≤ 50 ms per turn; H5 cold strong write tokens per
  session for R ≤ S × 1.05.
- The gate for PR 17 requires H1 through H5, no warm turn judged, zero lost
  turns, zero invariant failures, and the Laya replay gate. Route-failed
  recoveries are reported, never gated.
- Failure outcomes: H1 fails — routing stays off, and the report states the
  observed harm. H1 passes but H2 fails — the judge adds nothing over chance;
  shadow only. H3 fails — no value; off.
- Power: required pairs = 7.849 × p_disc / δ² at one-sided α 0.025 and power
  0.8. p_disc is observed in L1 or the calibration run and reported. If the
  observed p_disc exceeds the level's design value, the run is underpowered by
  construction and cannot pass H1 at that level; the report says so, and the
  budget is not silently extended.

## Levels and budget

Per-task-run cost assumptions and the level table are frozen from the design
(prereg source §8): S ≈ $2.2, R ≈ $1.8, N ≈ $1.8, C ≈ $0.15, T ≈ $1.9 per
task-run; calibration 80 tasks × (S + C) ≈ $190 at every level; L1 $1,000
(120 pairs, NO-GO only), L2 $2,500 (300 pairs, GO/NO-GO for main-conversation
cold-point routing), L3 $4,000 (480 pairs plus T and C contrasts). The runner
enforces the level with `--max-dollars <cap>`. The recommended level is L2,
run with L1's first 120 pairs as its first stage and a stop-for-harm boundary
preregistered with O'Brien–Fleming spending; the stage boundary values are
written into the registration before the first stage launches, and the level
itself is owner decision D12.
